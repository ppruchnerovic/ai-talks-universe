Description:
Software engineer Eugen Geist challenges the impulse to add specialized tools for every new requirement. Instead of reaching for MongoDB for document storage, Kafka for pub/sub, or Redis for queuing, he demonstrates how PostgreSQL's native features can handle these use cases effectively.

The talk covers practical implementations using LISTEN/NOTIFY for pub/sub messaging, SELECT FOR UPDATE SKIP LOCKED for distributed queues, and JSONB for flexible document storage. Geist also introduces vector extensions for AI workloads. Through live Python and SQL demonstrations, he shows how these patterns work in real projects.

The message isn't that PostgreSQL replaces everything forever, but that it can delay the need for specialized infrastructure until truly necessary. For freelancers, startups, and small teams, this approach means faster iteration, fewer operational headaches, and lower costs. By leveraging existing PostgreSQL installations, teams can focus on solving business problems rather than maintaining complex infrastructure stacks.
