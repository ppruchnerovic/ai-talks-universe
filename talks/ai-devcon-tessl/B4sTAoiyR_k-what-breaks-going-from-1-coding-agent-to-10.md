## Description

Running one coding agent is easy; running ten that share GitHub, Linear and CI turns software delivery into a distributed systems problem. James Moss, Member of Technical Staff at Tessl, shares five lessons from scaling Tessl's own software factory to 3.5x more merged PRs with the same team: shared state, stale assumptions, convergence, duplicate work, and budgets with stop conditions. Recorded at AI DevCon New York 2026.

What we cover:
– How Tessl's internal software factory grew to handle 85% of PRs
– Why independent tickets don't guarantee independent changes
– Catching stale assumptions when other agents change the code underneath
– Stopping review agents from talking in circles
– Idempotency and fault tolerance for factories built on third-party tools
– Budgets and stop conditions for multi-agent workflows
