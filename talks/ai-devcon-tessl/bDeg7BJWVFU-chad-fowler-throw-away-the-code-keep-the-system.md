## Description

What if your software continually regenerated itself, like a living system? Chad Fowler, CTO & GP at BlueYard and author of Regenerative Software, now in early access from O'Reilly, makes the case for treating code as a disposable, compiled artifact while the system itself is the asset. He covers the four things you must keep (intent, architecture, evaluations and provenance), demos Phoenix, his open-source take on the idea, and shares how to start with the most boring component you have. Recorded at AI DevCon New York 2026.

What we cover:
– From immutable infrastructure to disposable code
– Lessons from Heartbleed and a not-so-simple rewrite
– Why practices that sound reckless often add rigor
– Keeping intent, architecture, evaluations and provenance
– Specs as a graph, and a demo of Phoenix regenerating code
– Pace layers, compaction and where to start
