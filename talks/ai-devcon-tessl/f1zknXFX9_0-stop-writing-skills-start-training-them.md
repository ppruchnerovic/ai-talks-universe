## Description

Most teams write a skill once, patch it by hand when an agent misbehaves, and never measure whether it works. Shrey Shah, Senior AI Engineer at Microsoft, treats skills like model checkpoints instead: score them on a golden data set, let a second model propose small edits, and keep an edit only if held-out scores improve in a pairwise test, with git deciding what stays. He walks through a real training run, using LLM judges for subjective skills, and how to test the trainer itself. Recorded at AI DevCon New York 2026.

What we cover:
– Why skills are the next thing to evaluate and train
– Hand-editing skills is gradient descent, one bad PR at a time
– The training loop: score, edit, gate, then git commit or reset
– Script-based scorers and LLM judges
– Bounded edits, held-out scoring and remembering rejections
– A real training run, and how to test the trainer itself
