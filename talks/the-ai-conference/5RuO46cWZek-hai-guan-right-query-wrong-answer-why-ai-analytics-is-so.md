## Description

Every product team has an analysis backlog. Questions pile up, same metrics get re-sliced weekly, and when answers finally arrive, validation is manual and inconsistent. At many companies, the ratio is 80% execution mechanics to 20% actual thinking. We wanted the inverse. So we built AI Analyst - an open-source, multi-agent system powered by Claude Code that automates the full analytical workflow: from a business question to a validated, stakeholder-ready slide deck in roughly 30 minutes instead of days and weeks. What We built: The system orchestrates 18 specialized agents across a 4-phase pipeline - Frame, Analyze, Story, Deck - using DAG-based parallel execution. A Question Framing agent turns vague asks into testable hypotheses. Eight analysis agents run concurrently (descriptive, cohort, root cause, trend, validation, opportunity sizing). A Story Architect designs narrative beats before any chart is created - solving the "chart looking for a story" problem. A Chart Maker generates Storytelling-with-Data-styled visualizations with collision detection. Every output passes through 4-layer validation: structural, logical, business rules, and Simpson's Paradox checks, graded A through F. The system includes a knowledge layer that compounds over time: query archaeology captures proven SQL patterns, a corrections log ensures mistakes are never repeated, and organization-specific context (metrics definitions, business rules, team glossary) accumulates with use. It connects to any data source - CSV, DuckDB, Postgres, BigQuery, Snowflake. What I learned: The hardest part wasn't building the agents - it was getting an organization to trust and adopt AI-assisted analytics. Five real blockers emerged: security and legal approvals, data classification concerns, warehouse access, API cost ownership, and analyst skepticism. I'll share specific tactics for each, including the one that worked best: "show the output, not the pipeline." The critical design principle: AI can execute analysis fast, but it cannot tell you what question to ask or whether the answer makes business sense. We designed the system around human validation, not human replacement. The learning flywheel - run, review, spot errors, correct, store, improve - is what makes the system get meaningfully better over time. This talk is for data leaders, product managers, and engineers who want to democratize analytics without sacrificing rigor.
