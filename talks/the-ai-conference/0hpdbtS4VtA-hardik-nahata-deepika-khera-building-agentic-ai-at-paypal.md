## Description

An agent that can act on production systems is a new actor in the enterprise. It has credentials, and it can accomplish complex tasks across systems autonomously. That changes what the platform underneath has to provide: identity and authorization for non-human actors, transaction-grade reliability, and observability that treats every agent action as a first-class audited event. At PayPal we run a fleet of specialized agents on shared infrastructure — agents that write code, deploy models, and monitor agents. They sit on a common substrate: a certified agent/mcp registry, agent-to-agent delegation, unified model routing under latency and cost pressure, enterprise memory that persists across sessions, and a governed skills layer so capabilities are reused rather than rebuilt. We're now extending that substrate across cloud project boundaries, so agents owned by different teams and deployed in different environments can find and delegate to each other. Once agents cross those boundaries, identity and audit become essential. In regulated financial infrastructure, governance, security, and Responsible AI aren't a layer bolted on, they're the substrate the swarm of agents runs on. This talk walks through that architecture, then gets into the parts that were hard to learn: graph-based orchestration with typed state contracts, how we scaled the agent orchestrator, normalizing two agent protocols into one response contract, human-in-the-loop at the right moments, and agent memory that survives across sessions. You'll leave with patterns you can apply to your own systems and a clearer view of the platform capabilities these systems rely on.
