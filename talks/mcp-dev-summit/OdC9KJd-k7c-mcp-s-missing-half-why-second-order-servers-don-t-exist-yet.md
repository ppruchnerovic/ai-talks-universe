# MCP's Missing Half: Why Second-Order Servers Don't Exist Yet

## Description

Jerome Swannack, one of the first three engineers to build MCP at Anthropic, shares an idea he believes could solve a whole class of problems in the protocol: what if MCP was symmetric? By letting clients expose tools and resources back to servers, the MCP client becomes a switchboard, a routing and trust layer that finally makes second-order MCP servers practical.

Drawing on his background building rockets in New Zealand before joining Anthropic, Jerome walks through the cool MCP servers that should exist, why they are too painful to build today, and how a subtle protocol change could unlock them.

- Second-Order MCP Servers - The category that does not exist yet: servers that leverage your other installed MCP servers, like a deep-research agent or pluggable tool search.
- The LLM Operating System - Karpathy's idea of the LLM as a logic core, and why Jerome wants it broken apart and made composable with MCP.
- Why It Is So Hard Today - OAuth flows everywhere, trust spread across servers, and complexity smeared across the whole stack.
- The Cursed Attachment Problem - Why base64-encoding files into tool calls blows up your context window, and how symmetry makes it trivial.
- Symmetric MCP Explained - Putting tool calls and tool lists on the client so requests route through a central locus of trust.
- Code Mode, Made Pluggable - A generalized, standardized programmatic tool-calling server that plugs into any client supporting routing.
- Inter-Agent Communication - How an MCP server that is both client and server enables rich, runtime-expressive agent-to-agent messaging.
- User-Configurable Middleware - Composable safety scanners, retries, rate limiting, and tool search, like Unix pipes for agents.
- Sampling and Security - Why symmetric MCP improves sampling, plus the real UX and security tradeoffs of an open switchboard.

If you build MCP servers, design agent harnesses, or care about where the protocol goes next, this talk is a look at one possible future of MCP.
