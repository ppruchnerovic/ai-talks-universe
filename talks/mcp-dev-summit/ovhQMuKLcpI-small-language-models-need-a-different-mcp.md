## Description

Kierra Dotson is Director of AI Strategy at Further, a data and AI consulting company, and a speaker, writer, podcast host, and content creator focused on enterprise AI. Model Context Protocol was designed around three cloud assumptions - high bandwidth, persistent connectivity, and cheap compute - that completely break down at the edge, and she proposes concrete protocol changes to fix each one.

MCP's three cloud assumptions: How high bandwidth, persistent connections, and generous compute budgets are taken for granted in the current spec
Binary MCP with Protocol Buffers: Replacing JSON-RPC with protobuf to shrink tool call payloads from 2-5KB down to ~200 bytes - a 10-25x reduction - and speed up deserialization 10-50x
Semantic tool compression: Reducing tool schema payloads for SLMs with 4-8K context windows, so the schema doesn't consume the entire context before the first prompt arrives
Dynamic tool pruning: Allowing clients to pass session context so servers return only relevant tools, reducing hallucination and shrinking the prompt injection attack surface
MQTT store-and-forward transport: Using a local SQLite outbox and MQTT broker to make tool calls durable across network drops, sleep cycles, and battery death
Session continuity: Session IDs and sequence numbers in the MCP header so SLMs can resume mid-reasoning after a device wakes up
Content-addressable caching: An ETag-style hash exchange at the MCP layer to eliminate redundant sensor data downloads on constrained networks
Local-first resource discovery: A new mcp-local:// URI scheme that separates the data transport path (raw video/sensor frames) from the MCP intelligence layer, enabling real-time edge inference without routing footage through the MCP server
If you are building AI systems for manufacturing, healthcare, automotive, agriculture, or any edge environment where latency and connectivity cannot be taken for granted, this talk outlines the specific protocol changes that will make MCP viable for your stack.
