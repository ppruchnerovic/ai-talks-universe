## Description

A small refund feature passes through planning, implementation, local checks and pull request review before it is considered complete. Nnenna Ndukwe uses SignalPay, a deliberately narrow FastAPI payments application, to turn that sequence into quality gates for an AI coding agent. Participants choose a refund or capture retry workflow, identify the relevant payment rules and create both an implementation plan and a build execution plan. The point is to give the agent an explicit definition of the expected behavior, constraints, verification commands and evidence it must produce.

Ndukwe installs repository skills, connects Qodo and walks through the planning templates in Codex. The templates carry assumptions, risk, skill routing, acceptance criteria and the state of the current branch into implementation. After the agent opens a pull request, Qodo adds review findings informed by the codebase and organizational rules. The workshop shows how to inspect those findings, document fixes or deferrals and use a resolver skill to address the feedback and rerun verification. Audience questions test the boundaries: how rules are inferred and approved, how severity controls merge blocking, when verification should run again and how local checks relate to cloud review. The exercise finishes by resolving the remaining issues rather than treating a passing local run as the end of the workflow. Its reusable artifact is a structured process that keeps plans, code changes and review evidence connected.
