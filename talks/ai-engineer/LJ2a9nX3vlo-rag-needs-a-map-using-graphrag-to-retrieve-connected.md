## Description

An agent answering questions about a course needs more than the five chunks closest to a query. It also needs the connections between lessons, concepts, and the sources behind its answer. Nyah Macklin builds that retrieval path with Neo4j, combining vector search with a knowledge graph that people can inspect and query. The workshop starts with the difference between semantic similarity and relationships, then walks through GraphAcademy, an Aura database, and a Python environment. An LLM extracts entities and relationships from course material, embeddings support similarity search, and Cypher exposes the resulting structure. Vectors remain part of the system; the graph adds connected context and a way to answer questions that require traversal or aggregation.

The hands on build moves from a knowledge graph pipeline to an agent in Aura. Macklin creates a vector index, configures a lesson search tool, adds a retrieval query that returns related graph data, and enables natural language questions through text to Cypher. The agent answers a question about temperature using course content and displays its sources. A lesson count prompts a closer check of the underlying database query, showing why visible evidence matters even after the pipeline works. The final code walkthrough covers chunking, entity types, relationship types, and a schema that guides extraction rather than leaving the model to invent the graph's structure.
