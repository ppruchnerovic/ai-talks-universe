## Description

A student chatbot refuses to reveal grades, but its refusal exposes that it has access to them. Micah Silverman uses that capture the flag exercise to connect AI risks with familiar application security controls. A system prompt telling an assistant to keep data private leaves the data within reach; a restricted database view removes it from the model's available context. The six module course covers OWASP risks, shadow AI, threat modeling, MCP security, secure agentic development and red teaming. Direct and indirect prompt injection, poisoned tools and excessive agency all return to the same question: what can this system actually access and execute?

A live EVO demonstration inventories models, datasets, MCP servers and skills, then adds a policy that immediately flags a prohibited model already in a project. Silverman extends that inventory into proposed build gates and reviews how threat modeling changes when prompts, retrieved content and generated outputs cross trust boundaries. The MCP sections distinguish malicious tool descriptions from ordinary code vulnerabilities, pairing agent scans with dependency and source analysis. The secure development playbook adds isolated environments, constrained credentials, human approval and verified packages. In the final chatbot exercise, several prompts fail to disclose the confidential grades, underscoring the variability of model behavior and the need to test repeatedly. The controls sit outside the conversation as well as inside it.
