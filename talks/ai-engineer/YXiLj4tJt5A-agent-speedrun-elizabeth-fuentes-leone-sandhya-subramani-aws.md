## Description

A customer service agent looks up an account, checks an order, and handles a refund. The harder part is controlling what happens between those steps and keeping that control when the agent reaches production. Elizabeth Fuentes Leone and Sandhya Subramani build the workflow with Strands Agents, starting with a system prompt and three tools backed by mock customer data. They inspect messages and tool calls, add a conversational interface, then introduce a hook that limits tool invocations. Lowering the limit makes the constraint visible in a live test. An audience question separates blocking another tool call from ending the agent's turn, showing why a control needs a precise definition.

The next modules add skills and steering. Markdown instructions provide account troubleshooting, order tracking, and refund procedures when they are needed, while steering handlers check workflow order and response tone. The presenters compare programmatic checks with instructions left to a probabilistic model, then move the same customer service code into Amazon Bedrock AgentCore. The deployment walkthrough covers the application entry point, local testing, runtime setup, generated infrastructure, and a successful invocation. It also shows the observability configuration needed to inspect sessions, traces, and token use. The result is a path from a small notebook agent to a deployed service, with explicit places to add context, enforce constraints, and examine behavior.
