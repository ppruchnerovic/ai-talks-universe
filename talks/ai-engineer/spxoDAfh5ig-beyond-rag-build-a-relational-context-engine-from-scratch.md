## Description

Ask a vector store for the PRs you merged last week and it can hand back one that is semantically perfect and three years old. Peter Werry builds context engines at Unblocked, and his thesis is that RAG, meaning similarity search, is only half of retrieval. Engineering context lives in pull requests, review comments, tickets, wikis, and chat, and all of it has structure: authors, dates, states, labels, relationships. Dumping it all in a vector store and reranking fails any question with a temporal or structural half. So the other half is turning natural language into a real database query, where the model does not answer the question, it writes the query. The workshop walks six stacked pull requests that turn a stubbed query playground into a working engine over a GitHub repository.

Four pieces make the query reliable. Schema discovery samples three hundred documents and merges them into one tree, with procedural code rather than a model inferring types and enums. Identity resolution maps Peter to his GitHub login with simple fuzzy matching. Query planning passes the schema, forces a name extraction tool call, and includes the current date. Validation is deny by default: an allow list of operators keeps a function clause from running JavaScript on the server, and hidden metadata fields are wiped and reinjected for tenant isolation. A retry loop feeds validation and execution errors back to the model, which exposes the need for full text search when exact match fails. The same engine then powers a chat agent, and the Q&A covers scaling schemas with summaries, continuous ingestion, why Slack holds the why questions, MCP, and hybrid search.
