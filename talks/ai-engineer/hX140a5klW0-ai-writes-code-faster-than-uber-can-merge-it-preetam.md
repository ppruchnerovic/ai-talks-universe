## Description

Preetam Dwivedi and Manjari Akella of Uber's developer platform team share how AI-driven code changes pushed Uber's merge pipeline to its limits, across monorepos where more than 5,000 developers land tens of thousands of commits a week. They walk through three changes to SubmitQueue that kept changes landing without long waits: admission gating that sorts cheap changes from expensive ones, a deferral queue that softens the impact on developers, and conflict relaxation that lets more changes run in parallel. They also explain how Stovepipe checks changes after they land and tracks the last verified-good state of trunk, why Uber moved from an always-green trunk to a hybrid approach, and what they're building next.
