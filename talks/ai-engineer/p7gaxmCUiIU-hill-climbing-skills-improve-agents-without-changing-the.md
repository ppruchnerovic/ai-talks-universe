## Description

An agent succeeds at a flight search, then fails on its next iteration. Shubhankar Srivastava uses that uneven progress to show how browser agents can learn a task without changing model weights. His AutoBrowse loop pairs a doer that operates the browser with a teacher that reads screenshots, traces and results after each run. The teacher writes lessons into a strategy file, and the next attempt starts with those lessons instead of starting from zero. The flight demo discovers that a URL can encode the search directly, avoiding repeated calendar clicks and an awkward time filter.

The final artifact is a skill file that future agents can reuse. Earlier runs on a conference schedule and restaurant search show how the file preserves navigation choices, waiting behavior and site specific constraints, while replays make the claimed results inspectable. Srivastava then explains what another domain would need to use the same approach: an environment that can be replayed and an outcome that can be verified. Questions expose the limits of that requirement, especially when finding an acceptable flight is easier to judge than finding the best one. The discussion explores task specific versus general skills, different optimization goals, iteration costs and how to measure the verifier itself. For changing websites, he describes monitoring and failure triggered repair loops that produce changes for human review. Prompt injection adds another constraint: generated skills need scrutiny alongside controls on inputs, allowed actions and destinations.
