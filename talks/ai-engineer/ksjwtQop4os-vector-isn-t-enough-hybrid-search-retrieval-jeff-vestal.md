## Description

An agent diagnoses exit code 137 by retrieving documentation, explaining an out of memory failure, and pointing to settings that can prevent it. Its answer depends on the search results it receives, and its citations lead back to the underlying documents. Jeff Vestal and James Williams work backward from that agent behavior to the retrieval layer in Elasticsearch. The hands on labs compare semantic search with BM25, showing why similar meaning can miss an exact identifier and why exact keywords can miss a paraphrase. Participants run queries in the Dev Tools console and Python notebooks, inspect rankings, and combine both methods rather than assuming one search strategy fits every question.

The workshop explains reciprocal rank fusion, which combines result positions, and linear combination, which normalizes scores and exposes weights for tuning. Filtering narrows the candidate pool, judgment sets help assess changes, and search templates offer a way to route different query types to different strategies. The Agent Builder demonstration connects retrieval to tools, skills, repeated searches, and answers with sources that viewers can inspect. A bonus section compares pointwise and listwise reranking and asks when improved precision justifies another inference step. Questions cover chunking, embedding consistency, quantization, latency, and the limits of automatic tuning. The through line is practical: improve and measure the evidence reaching an agent before expecting the model to rescue poor retrieval.
