## Description

Handwritten flight logs and heavily redacted PDFs stand between a pile of documents and a searchable product. Palak Agarwal and Omar Alhait show how Reducto turned the Epstein files into structured data for JMail and its related applications. Agarwal introduces the document processing layer; Alhait walks through the extraction pipeline behind JFlights, showing how a schema turns difficult pages into usable records. The workflow starts with parsing, tests extraction results in Studio, and exposes the configured pipeline through an API call or code snippet. The product demonstration makes the bottleneck visible: reading order, handwriting, layout, and inconsistent documents need to survive extraction before an interface can make them useful.

A live resume example shows how to generate a JSON schema, upload documents, and inspect the resulting fields. The discussion distinguishes a quick schema from one informed by parsed document content, then explores nested fields, citations, figures, and the choice between OCR and PDF metadata. Alhait also describes why drawing a black box over text can leave information exposed, and how the team handled material intended to remain redacted. Questions move from model training and document specific configurations to practical evaluation: inspect a small sample first, then build a representative benchmark before scaling. The recording ends with instructions for an interactive extraction exercise, connecting the JMail case study to participants' own document workflows.
